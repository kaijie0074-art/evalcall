- 日期：2026-07-16
- 页面：`site-deploy/app.html`
- 范围：六步流程的全部 47 个输入、处理、输出节点

## 改造结果

节点详情由“三段功能说明”升级为真实实现剖面。每个节点现在分别展示：

1. 真实代码模块与函数 / API 入口。
2. 输入字段及其数据类型或业务含义。
3. 输出字段、文件与版本化产物。
4. 四段式具体执行顺序。
5. 失败条件与系统兜底行为。
6. 对应自动化验收文件。
7. 当前批次的真实数量、哈希、门禁、证据等运行痕迹。

所有节点使用独立实现配置，共计 47 个 `NODE_IMPLEMENTATION` 条目，不使用一份通用说明冒充不同节点。

## 浏览器验收样例

### 第 2 步：拆成原子检查点

- 代码入口：`evalcall/compiler.py · compile_task() / compile_task_fast() · POST /api/compile`
- 输入：任务正文、编译模型配置、`max_items`
- 输出：原子 `Checkpoint[]`
- 执行：拆解单一行为 → 解析 JSON → 补齐类型与严重度 → 去重和限制现场条目数
- 失败兜底：后端失败返回准确错误；fast 编译仅用于明确标注的现场探针
- 自动验收：`tests/test_compiler_calibration.py`

### 第 2 步：Checklist 版本

- 代码入口：`evalcall/demo_server.py · _compile_session() · POST /api/compile response`
- 输入：L0 + L1 checkpoints、session task_id
- 输出：`checklist.json`、`checklist_sha256`、approved / samples
- 执行：合并规则 → 写文件 → 计算 SHA-256 → 返回样例和站内产物地址
- 失败兜底：来源校验通过且无 `needs_review` 才标记 approved
- 自动验收：`tests/test_demo_server.py`

两个节点的代码、数据契约、执行链与保护规则均不同，确认详情不是换标题的同一份模板内容。
