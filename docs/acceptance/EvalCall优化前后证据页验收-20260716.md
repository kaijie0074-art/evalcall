# EvalCall 优化前后证据页验收

- 日期：2026-07-16
- 页面：`site-deploy/app.html` 第 6 步
- 主样例：配送时间改约，`delivery-baseline-v1 → delivery-guarded-v2`

## 页面结构

1. 优化前 / 优化后门禁结论。
2. 用户输入、SOP、Checklist、Judge 四类同尺锁定证明。
3. 打回、P0、平均分、履约率和人工复核状态迁移。
4. 同一用户输入下的 v1 / v2 原文回复对照。
5. 检查点 `fail→pass`、`pass→fail`、`fail→fail` 迁移。
6. 证据边界、退化项与下一轮优化方向。

## 真实结果口径

- 上线门禁：打回 → 可上线。
- 通话打回：3/10 → 0/10。
- P0 触发：3 → 0。
- 平均分：62.5 → 91.4。
- 履约率：40% → 40%，未提升。
- 逐项判定：14 项修复、11 项退化、12 项仍失败。

页面明确给出“门禁风险已清零，但履约率未提升”的结论，并单独展示退化和未解决项，不把局部改善包装为全面提升。
